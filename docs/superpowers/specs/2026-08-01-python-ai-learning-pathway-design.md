# Python 与 AI 学习路径设计

> 历史说明：这份 12 周通用路线已于 2026-09-01 被 [6 周 AI 应用工程核心路线](../../ai-application-core-6-week-roadmap.md) 替代。文件保留用于解释既有 1–5 周课程的设计背景，不再作为当前学习计划。

## 1. 背景与目标

学习者是一名以 Java、Spring Boot 和微服务架构为主要技术栈的软件工程师，目前没有 Python 语言经验。学习目标是掌握 Python 工程开发，并进一步进入数据处理、经典机器学习和 AI 应用开发领域。

学习者每周可投入 10 小时以上。数学方面学过线性代数、概率统计和微积分，但知识有所生疏。课程采用结合代码按需复习数学的方式，不设置独立、漫长的数学前置阶段。

综合项目方向暂不预设。在接触机器学习服务、RAG 和工具调用等方向后，于课程后期根据兴趣和实际表现选题。

## 2. 教学策略

课程采用螺旋式项目驱动方式。每个阶段按照“核心概念、短练习、可运行项目、工程化改进”推进，并在后续项目中持续复用和深化已经学习的知识。

讲解会利用学习者的 Java 背景，重点比较 Python 与 Java 在以下方面的差异：

- 动态类型与类型标注
- 对象模型、协议与数据模型
- 异常与资源管理
- 包、模块、虚拟环境和依赖管理
- 生成器、迭代器及异步编程
- FastAPI 与 Spring Boot 的设计差异
- Python 数据与 AI 生态的工程实践

课程不会重复讲解学习者已经掌握的通用编程概念。必要时通过挑战题判断是否可以跳过某个主题。

## 3. 周期与时间分配

课程默认持续 12 周，每周投入 10–15 小时。实际进度按掌握情况调整，不与自然日机械绑定。

每周时间建议如下：

- 概念讲解与 Java 对照：20%
- 小型编码练习：25%
- 项目开发：45%
- 复盘、测试与延伸阅读：10%

## 6. 项目演进

课程使用一条持续演进的项目主线：

1. 日志分析 CLI
2. 通用数据处理管道
3. 公开数据分析与预测模型
4. FastAPI 模型服务
5. LLM、RAG 或工具调用综合应用

每个阶段成果独立可运行，同时复用前一阶段的工程实践。项目单元保持边界清晰，使数据读取、转换、训练、评估和服务接口能够分别测试和替换。

## 7. 每课互动方式

每课采用以下结构：

1. 说明本课目标和完成标准。
2. 讲解核心概念，并与 Java 或 Spring Boot 对照。
3. 完成若干 5–15 分钟的短练习。
4. 实现带有输入输出示例和验收标准的项目任务。
5. 从正确性、Python 风格、类型设计、测试和工程结构方面进行代码评审。
6. 通过复盘测验识别薄弱点，决定继续推进或局部补强。

帮助采用递进方式：默认先提供目标、约束、提示和测试反馈；学习者卡住时逐级增加提示；只有在需要复盘或多次尝试仍未解决时提供完整参考实现。

## 8. 公开资源策略

每周开始前核验并提供与本周主题直接相关的公开资源。优先级如下：

1. Python、NumPy、Pandas、scikit-learn、FastAPI 等项目的官方文档与教程
2. Kaggle Learn 的免费短课程和公开数据集
3. Google Machine Learning Crash Course
4. Hugging Face Course
5. Full Stack Deep Learning 的相关公开章节

资源以少而精为原则。每周区分必读、选读和查阅资料，避免堆积链接。涉及快速变化的工具、API 或课程内容时，在使用前重新核验。

## 9. 工作区结构

课程执行阶段采用以下目录：

```text
lessons/       每课讲义与示例
exercises/     小练习
projects/      阶段项目
resources/     公开资源索引
progress/      学习记录与复盘
```

`progress/` 中记录已完成课程、练习结果、薄弱点、下一步任务和综合项目候选方向。跨天继续学习时，以该记录作为恢复上下文的依据。

## 10. 验收标准

完成课程后，学习者应当能够：

- 独立构建带类型标注、测试、日志和依赖管理的小型 Python 应用。
- 使用 NumPy 和 Pandas 完成数据处理和探索性分析。
- 使用 scikit-learn 完成数据清洗、训练、评估和基础模型解释，并说明模型表现与局限。
- 使用 FastAPI 将模型封装为经过测试的 API。
- 实现并评估一个包含 LLM、RAG 或工具调用的 AI 应用。
- 根据问题性质判断应使用确定性规则、传统机器学习还是大语言模型。
- 提交一个包含运行说明、测试、评估结果和设计取舍的综合项目。

## 11. 调整规则

- 若挑战题显示某主题已掌握，则缩短讲解并直接进入项目任务。
- 若复盘测验或项目暴露基础薄弱点，则安排针对性练习，不整周回退。
- 若每周实际投入高于 15 小时，可增加选做挑战，但不提前引入与主线无关的框架。
- 第 10 周结束后，根据已经完成的原型、兴趣和实际表现确定第 12 周综合项目方向。
- 如 12 周不足以达到综合项目验收标准，则延长项目迭代，不降低完成标准。
